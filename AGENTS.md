# AGENTS.md

DSH plugin: MCP server manager for DeepSeek Harness (web profile). Settings → MCP page for HTTP (OAuth PKCE + RFC 7591 dynamic client registration, static Bearer token, or no auth) and local stdio MCP servers, whose tools are registered as `mcp__<name>__<rawName>` native tools.

## Layout

Plugin **source** is `lib/index.js`, `lib/client.js` and the focused modules under `lib/oauth/`, `lib/auth/`, `lib/servers/` and `lib/import/` — keep it that way unless a refactor is explicitly requested (tests live under `test/`):

- `lib/index.js` — **host half** (Node.js): HTTP API on the DSH GUI webserver under `/mcp-manager/api/*`, OAuth flow orchestration (start, exchange, reconnect), both MCP transports, tool registration into `ctx.tools`, state persistence.
- `lib/oauth/callback-manager.js` — the loopback HTTP listeners that receive OAuth callbacks: one port per listener, one socket per bound loopback address, path routing and refcounted release.
- `lib/oauth/redirect-resolver.js` — pure policy: loopback predicates, callback-path normalization, global configuration validation, override parsing, and the override → fixed → automatic precedence.
- `lib/oauth/session-store.js` — pending authorization sessions keyed by the OAuth `state` (single use, ten-minute expiry, per-connection index).
- `lib/oauth/callback-page.js` — the HTML page and the write helper the listeners use.
- `lib/servers/config.js` — the pure configuration helpers every write path shares: field validation with a named `field`, the single `buildServerEntry` (and the workspace loader/builder on top of it), `patchServerRow`, `sameServerConfig`, and the OAuth identity predicate `sameAuthIdentity` / `keepsStoredSession`.
- `lib/import/format.js` — the `mcpServers` document: envelope parsing, per-entry normalization with the import-only transport inference, and the pure plan (`planImport`) that classifies each entry.
- `lib/import/apply.js` — executes a plan through injected ports (`readWorkspaceRaw`, `writeWorkspaceRaw`, `saveState`, `connect`, `disconnect`, `cancelSessions`, `rescan`), so it is testable without a plugin context.
- `lib/auth/gate.js` — the authentication waiters: one entry per server key, one deadline shared by its callers, injected clock/timers, abort wiring, cancellation by session, the read-only attention snapshot and the `failed`/`clearFailure` text shown by the banner. It knows nothing about transports, tools or plugin state.
- `lib/auth/recovery.js` — `AuthRequiredError`, `withAuthRecovery` (first attempt → wait → one retry) and `authFailureMessage`, the only place the model-facing authentication error is built. The host injects the state recorder, the flow-release hook and the redactor.
- `lib/client.js` — **client half** (browser): a `window.__ModuleLoader__.load(...)` factory using `react.createElement` (no JSX, no bundler). Registers the Settings → MCP tab via the `settings.section` slot and the conversation authentication banner via `conversation.input.dock`. **UI is bilingual** (Simplified Chinese and English; follows DSH’s Settings → General → Language preference) — every user-visible string is resolved through `t` from the `mcp` locale namespace, never hardcoded.
- `cordis.patch.yml` — bundle patch that activates the plugin row (`dsh.bundle.patch` in package.json).
- `test/*.test.js` — `node --test` unit tests over the host half's exported helpers plus a stubbed-context `apply()` API smoke test (not shipped: `files` lists only `lib/*`). The client suites share `test/helpers/client-harness.js`, which runs the real `lib/client.js` factory in `node:vm` over a minimal React stub, records every slot registration (`slot(name)`, `slotOptions(name)`) and does not model effect dependency arrays. Host integration suites share `test/helpers/plugin-harness.js` (stub context with recorded global and per-agent tool registries) and `test/helpers/oauth-harness.js` (a loopback MCP + authorization server with token revocation, a refresh-rejecting mode and recorded `toolCalls`).
- `README.md` / `README.zh-CN.md` — keep both in sync on behavior changes.

## Architecture rules

- Two halves talk only through the same-origin JSON API `/mcp-manager/api/*`; the client never touches Node APIs and the host never renders UI.
- OAuth callbacks are served by listeners this plugin owns, bound to loopback only — never by the GUI webserver, and never through a request-derived origin. The callback URL carries no MCP identifier: the path defaults to `/callback` (configurable globally) and the OAuth `state` is the only routing key.
- Redirect resolution lives in `lib/oauth/redirect-resolver.js` and nowhere else: per-server `redirectUrl` override → global `oauthCallback` fixed configuration → automatic allocation. An override without a port (or path) inherits the fixed global port/path, and otherwise allocates automatically with `/callback`. `localhost` binds both loopback families (IPv4 fallback when `::1` is unavailable); an explicit port is bound verbatim and a busy one fails loudly — never a silent fallback. Only loopback literals and `http` are accepted: `publicOrigins` no longer participates, and a stored non-loopback `https` value fails the next authentication while staying untouched.
- The resolved URI is pinned in the session when authorization starts and replayed by registration, authorize and token exchange. Client registration is bound to the exact redirect URI and re-registers if it changes; saving an override must not drop tokens (the next authentication re-registers lazily), so the field stays out of the PUT identity tuple.
- Listeners are refcounted per port: `acquire` returns a single-use grant, and only that grant may release its use — never a bare port/path pair, which a later flow may have re-created. Release only **after** the callback page is written (closing waits for the open connection, so releasing first deadlocks), keep the listener while any flow still needs it, dedupe concurrent binds of the same address on one in-flight promise, and close everything on unload. Token refresh must never require a listener.
- Authorization sessions are keyed by `state` (`lib/oauth/session-store.js`): 32 random bytes, single use with a tombstone so a replay is explained, ten-minute TTL, several concurrent flows per server, and token writes only for the session's own connection.
- Token state (`~/.dsh/mcp-manager.json`) contains secrets — never log tokens; treat the file as sensitive.
- All state/configuration writes and OAuth refreshes share the state-file lock, with FIFO acquisition inside a process. Preserve changed-field merging against fresh disk state and unique server IDs; a refresh that already holds the lock must persist without reacquiring it.
- Adopting another process's OAuth state is a read, not a local change: rebase `savedSnapshot` so later settings saves cannot overwrite a newer rotation. If a rotated pair cannot be persisted, retain it in memory and prevent another refresh until successful reauthorization; never replay a spent refresh token.
- Never reclaim a live owner's state lock. Stale-owner recovery uses an exclusive reclaimer guard and rechecks age, liveness, and ownership before unlinking; an orphaned reclaimer guard fails closed pending verified operator recovery. Cover changes with the concurrency, adoption, persistence-failure, and stale-lock cases in `test/oauth-resource.test.js`.
- Tool name convention `mcp__<server>__<raw>` with `[^A-Za-z0-9_-]` → `_` normalization and a 64-char cap (sha256 suffix on overflow) — must match the built-in `@deepseek-ai/dsh-mcp-client`.
- Tool schemas must pass through `sanitizeValue`/`convParams` (registry accepts only a raw JSON-Schema subset; unsupported vocabulary degrades to unconstrained).
- stdio transport: `child_process.spawn`, newline-delimited JSON-RPC over stdin/stdout. Reconnect must reap the old child first; `ctx.effect` teardown kills all children on unload. `args` are quote-aware tokenized with **no shell expansion**. On Windows `shell: true` makes Node join command + args with bare spaces and add no quoting, so every token must pass through `quoteWindowsToken` (idempotent for already-quoted values) or `cmd.exe` truncates paths containing spaces.
- Loaded state is migrated once in `apply()` via `migrateLoadedState`: missing or duplicate `server.id` values are backfilled (live status and `/servers/:id/*` are id-keyed, so a missing id 404s every id-addressed API) and legacy `[{ name, value }]` env/header arrays are normalized to maps. Persist immediately when it reports a change.
- HTTP transport: streamable HTTP (JSON-RPC POST, `Mcp-Session-Id` header, SSE-or-JSON response fallback in `parseRpc`). A 401 triggers one `refresh_token` retry, then reconnect; every 401 also parses `WWW-Authenticate` for `resource_metadata` and caches that URL on `server.oauth`.
- OAuth discovery is ordered, never a single guess: cached/401-advertised RFC 9728 protected-resource metadata (path-inserted, then bare) → its `authorization_servers[0]` → RFC 8414 metadata at the **path-inserted** well-known URL (`wellKnownUrl`), then `openid-configuration`, then the naive `${issuer}/.well-known/oauth-authorization-server`; guessing `${origin}/oauth/*` is the last resort and returns `source: 'fallback'`. `issuerOf` must stay pure (no I/O); the editor invalidates cached OAuth state by comparing the MCP endpoint's **origin** across an edit — never a resolved issuer against a naive one, because an authorization server on another origin or under a path (GitHub, Figma) would then lose its tokens on every save. `server.oauth.authorizationServer` / `server.oauth.resourceMetadataUrl` / `server.oauth.challengeScope` are the only non-secret discovery caches, and `discoverAndPersist` writes them only when they changed. `oauth.grantedScope` and the transient `oauth.insufficientScope` record what the token actually carried and what a 403 asked for; a **403** challenge must never write `challengeScope` (it names scopes required on top of the current grant, so caching it would replace the advertised base selection instead of extending it).
- OAuth client credentials: `redirectUrl` (non-secret per-server redirect override: `http://host[:port][/path]` with a loopback host, validated by the resolver's parser, carried by `applyOauthFields`/`sameServerConfig`/both views/`EXTERNAL_AUTH_FIELDS`/`buildWorkspaceEntry`, exposed with `redirectMode`, the effective URI when the port is knowable, the last used URI, and the pending-registration/warning flags — all computed host-side because only the host knows the global configuration), `clientId` (manual, non-secret — skips RFC 7591 entirely and is never re-registered), `clientSecretEnv` (an environment-variable **name** only; the value is read per request and sent as `client_secret` — `client_secret_post` is the only supported method), `clientName` (optional RFC 7591 `client_name`, default `dsh-mcp-manager-<server>`, printable ASCII ≤128 chars — providers such as Meta and Figma gate registration on an exact name allowlist; a changed name re-registers and drops the old client's registration and tokens, and a missing `oauth.clientName` on a pre-0.16.1 registration counts as the default so upgrades do not re-register), and `scope` (manual override for the `scope` authorization parameter; a hand-edited `oauth.scope` is honoured too). Without one, `effectiveScope` picks the 401 challenge `scope` (cached as `oauth.challengeScope`) → RFC 9728 `scopes_supported` → RFC 8414 `scopes_supported` → none, plus any scopes from an `insufficient_scope` 403 (`oauth.insufficientScope`, cleared by the next token grant). A 403 on an authenticated OAuth request (only an explicit `insufficient_scope` for `tools/call`) becomes `needs-auth` with an *insufficient scope* message, never a retry loop. All four are OAuth-only: switching to `static`/`none`/stdio deletes them, and a changed `clientId`/`clientSecretEnv`/endpoint origin drops `server.oauth` (a changed `clientName` does too, but only for a dynamically registered client — a manual Client ID never registers, so `registrationNameKey` returns `''` there; a rename that changes the derived default name counts, so the pre-edit identity is captured before `server.name` is replaced). Validation lives in `parseOauthFields` (side-effect free) + `applyOauthFields`; `sameServerConfig` and both `*View` helpers must carry the fields or workspace edits silently no-op. Dynamic registration requests `client_secret_post` only when the AS metadata advertises it and otherwise `none` (the public-client default MCP expects), and persists an issued `client_secret` as `oauth.clientSecret` in the 0600 state file; `clientSecretOf` prefers `clientSecretEnv` and otherwise returns it, sending it on both exchange and refresh only when the registration requested `client_secret_post` (persisted as `oauth.tokenEndpointAuthMethod`) and no manual `clientId` is configured — a manual client never registers, and a `none` registration must not present a secret it did not ask to use. A re-registration that replaces the client (changed name or redirect origin) drops the old token pair eagerly — the new client cannot refresh it — instead of failing a later refresh. That secret is never exposed by a view, an API response or the attempt log. Coverage: `test/oauth-dcr-client-name.test.js`.
- HTTP auth modes are `oauth` | `static` | `none`, normalized in exactly one place (`normalizeAuthMode`). `none` is exempt from the credential gate (`hasToken` → true) and `accessToken` must return `''` for it so a stale attached OAuth token is never sent; switching to `none` in the editor also drops `server.oauth`.
- JSON import (`POST /mcp-manager/api/import`) is one contract for both scopes and both modes: `mode: "import"` creates and updates only, `mode: "edit"` treats the document as the whole scope and may delete. `dryRun` returns the plan and writes nothing; an application re-validates the submitted document instead of trusting a cached plan. A batch is validated completely before any write, so one invalid entry aborts it with the entry name and field; the limits are 200 entries and 1 MiB. Classification is `new` / `update` / `unchanged` / `conflict` / `invalid` / `delete`, a cross-scope name is a `conflict` resolved per entry as `keep` or `replace`, and `replace` moves the existing server into the target scope. Structural fields come from the entry, an omitted OAuth credential field and an empty `tokenEnv` inherit, explicit `""` clears an OAuth field, unknown entry keys (including `oauth`/`tokens`/`staticToken`) are discarded, and unknown top-level workspace keys survive. The importer never touches `enabled`/`disabled`, never starts an authorization, and never disconnects a server whose configuration did not change; a stored session survives while `sameAuthIdentity` holds and moves across scopes on a `replace`.
- Disable/enable is global per profile: disable unregisters tools + drops the connection but persists config and tokens; enable reconnects without re-auth.
- On-demand broker hiding is version-dependent. DSH `0.2.2` and newer assemble the model-facing tool list from the registry **after** the `system-prompt/assemble` waterfall and never pass `tools` in it, so the broker marks every `mcp__*` definition with `deferLoading: true`; `0.2.1` and older still pass `tools` to the waterfall and are filtered in the hook, which must treat a missing `tools` array as "this harness owns the list" rather than reading it. The marker is harness-preserved through schema projection and keeps definitions registered and executable (so `mcp_execute_tool` can dispatch); whether a provider request actually omits a deferred tool is provider-side — the DeepSeek adapter forwards it as `defer_loading`, the pi-ai adapter filters it out, and routes without tool-update support send the schema unchanged. The marker is captured per registration: `registrationSignature` includes it, and `setOnDemandToolInjection` re-registers live global and workspace registrations so the toggle takes effect without a reconnect. Presentation is detected from the executor's prompt sections (code/PTC own them, native owns none), with the waterfall payload as a second signal on harnesses that still supply one; a code presentation keeps its full catalog and bypasses the direct-call guard. On `0.2.2` a program cannot call `mcp_execute_tool` (the PTC executor makes only `run_code` directly callable), so code presentations call `mcp__*` tools directly. Broker dispatch sends **one** `ctx.tools.execute()` call carrying both shapes — the `0.2.2` single-call batch (`calls: [{ id, name, arguments: <JSON string> }]`) and the flat pre-0.2.2 fields (`callId`/`name`/`arguments`/`parent`, plus the step's `toolSet` when supplied) — then unwraps `results[0].result` when the batch form answers. `0.2.2` also drops the parent token, so an in-flight dispatch is tracked per agent to let the guard admit its nested call; keep both mechanisms or the guard starts denying the broker's own dispatch.
- Tool-call timeouts resolve as server `timeout` → plugin `config.toolCallTimeoutMs` → 60000 ms. Valid finite numbers or numeric strings at least 1000 are floored. Apply the budget to `tools/call` across stdio, Streamable HTTP and legacy HTTP-with-SSE; do not silently change initialization or tool-listing budgets. Preserve chained timers above Node's timer limit, clearing an override, and workspace reconnection after edits. A local timeout does not prove remote cancellation, so avoid automatically replaying a potentially mutating call.

- Authentication waits: an authenticated `tools/call` rejected with `401` or an explicit `403 insufficient_scope` that a refresh cannot repair throws `AuthRequiredError`. For an OAuth server the call waits in `lib/auth/gate.js` (budget `config.authWaitMs`, default `120000`, minimum `1000`), the connection moves to `needs-auth` through `noteAuthFailure`, and any successful `connect`/workspace reconnect calls `gate.authenticated(serverKey(server))` — which resumes every waiting call of that server, across sessions, for exactly one retry with the same arguments. `static`/`stdio` servers fail immediately with the actionable message, and `initialize`/`tools/list` failures never wait. The retry resolves the live connection (`live.get(server.id)` / the workspace record) because a reauthorization replaces the connection object; never reuse the one captured at registration. `GET /mcp-manager/api/attention` is a read-only listing of the calls currently waiting — one row per server and session with the reason, the last failed attempt, the phase, the call count and the time left — and `POST /mcp-manager/api/attention/cancel {sessionId, serverId}` settles that session's calls and releases a pending flow only when no other waiter remains. Disabling or deleting a server settles its waiters as `disabled` (a workspace rename does too; a global rename reconnects and can resume them). Neither endpoint carries a token, a client secret or an authorization URL. A failed authorization attempt is recorded with `gate.failed()` and does NOT settle the callers; they end by a later success, a cancel or the budget. The conversation banner (`conversation.input.dock`, id `mcp-manager-auth`, order `10`) polls the listing every 2s, filters by the owning `sessionId` (a workspace server is registered only into its own workspace's agents, so the session filter is what scopes it), renders one row per waiting server with Authenticate and Cancel, and disappears with the last waiting call. The two settings rows and the banner share `requestAuthorization`/`startAuthorizationAction`; a blocked `window.open` keeps a manual link. The callback page copy points at the conversation banner as well as Settings → MCP.
- Workspace isolation: `<workspace>/.dsh/dshmm/mcp.json` declares per-workspace servers; `exclude` masks global servers for that workspace through `tools.restrict({ deny })` on each agent. `disabled` is the per-workspace off switch and covers **both** global and workspace-local names: a disabled global joins the restrict deny set, while a disabled local is never connected or registered (its row stays visible with status `disabled`, and its declaration plus OAuth tokens are retained so re-enabling needs no re-add or re-auth). `POST /mcp-manager/api/workspaces/server-state {path,name,enabled}` writes the list, dropping the matching legacy `exclude` entry so the two lists cannot disagree (enabling clears both); unknown `disabled` names are ignored and logged only when the list changes. Workspace writes preserve unknown keys. Coverage: `test/workspace-disable.test.js` (scoping, existing and new agents, hot reload, disabled-local row and projection, rename/delete list maintenance with the shared-global-name guard, hand-edited name normalization) and the client row-switch test. Reader and writers share `normalizeNameList` (trim + dedupe); an emptied `exclude`/`disabled` list is removed from the file. A workspace edit keeps an OAuth field the payload omits (`buildWorkspaceEntry(body, current)`, same as the global PUT) and preserves the stored workspace token slot only while the client identity (`clientId`/`clientSecretEnv`/dynamic `clientName`) and issuer are unchanged.
- Diagnostics are an in-memory `Map<serverId, entry[]>` ring buffer (20 entries/server, ≤500 chars each) written by `recordAttempt` and read by `GET /mcp-manager/api/servers/:id/logs`. Redaction happens **on write**, never on render; for OAuth provider responses and MCP transport errors it runs on the full body **before** truncation — a JSON credential cut at the cutoff loses its closing quote, so `redact(text.slice(0,n))` would keep its prefix: query-string `code`/`state`/`client_secret`/`access_token`/`refresh_token` are stripped, JSON-quoted credential fields (`{"client_secret":"…"}` in a provider error body) are masked too, `Authorization` values are never stored, and `Bearer …` is masked. Error text shown on the OAuth callback page goes through the same redactor. Tool-list refresh failures use `describeError` before reaching the host logger. Regression coverage: `test/transport-redaction.test.js` and the real-Loader snapshot in `scripts/verify-transport-redaction-dsh.mjs`. Logs are never persisted (a log file would be a new secret-at-rest surface) — the durable record stays `ctx.logger`. Workspace logs survive a rescan because their ids are deterministic (`workspaceServerId`); deleting a server clears its log.
- Tool inventory: `GET /mcp-manager/api/servers/:id/tools` returns the live connection's raw `tools/list` names, sorted, and answers `409` when that connection is not `connected` (an unknown id is `404`). It reuses the id routing that serves `/logs`, so it resolves a global server, a loaded workspace server, and a workspace row projected from disk; names come from `conn.tools` keys (global) and `wc.tools` names (workspace), never from the public normalized name. `GET /servers` and `GET /workspaces` stay count-only — never add names there. The client fetches on expand and after each poll while the card stays expanded (`McpContent` owns the request and ignores a stale response by id); the shared card only renders `{ server, tools }` and the per-status empty messages. Coverage: `test/tool-inventory.test.js`, `test/client-tools.test.js`.
- On-demand default: an absent `onDemandToolInjection` resolves to enabled (`onDemandEnabled()`); only an explicit `false` disables the broker, and the absent value is never written back by the default. Code/PTC presentations keep the full catalog (`docs/on-demand-code-mode.md`). Tests that exercise the state-file lock through `POST /settings/on-demand` must post the value opposite to the effective default, because a no-op toggle never acquires the lock.
- UI is bilingual: the `mcp` locale namespace holds `zh` and `en` dictionaries with the **same key set** — add new strings to both. Register them with `ctx.effect(() => ctx.locale.register("mcp", { zh, en }), "dsh-mcp-manager: dictionaries")`. The client injects `locale` and declares `@deepseek-ai/dsh-client-locale` in `dsh.client.inject`. Register `settings.section` with `locale: "mcp"`: its component receives the standard `t` prop and passes it to children. Use a bound `t` for the slot label callback. DSH owns language selection (Settings → General → Language), browser fallback, persistence, and live updates. Do not add a plugin language selector, language state, or language API. The server card starts collapsed and expands to the raw tool list, the action row and the log panel; a workspace row uses the same card. The add action sits in the toolbar beside the server search (global view) or the workspace selector (workspace view), never in the page header. `GET /settings` exposes the effective `onDemandToolInjection` (including the absent-field default), the global `oauthCallback` configuration and its live `callbackStatus` (listeners + last error); legacy `language` values in the plugin state file remain untouched and unused. Server-supplied diagnostics (MCP error text, tool descriptions) stay in their original language.

## Commands

No build/lint scripts. It's plain ESM with zero dependencies (Node built-ins only; Node `^22.19 || >=24`). `package.json` declares exactly one script, `test`:

```sh
npm test             # = node --test; default discovery picks up test/*.test.js
node --test test/mcp-image-projection.test.js   # single file
```

Verify behavior changes by installing into a live DSH web profile:

```sh
npx -p @deepseek-ai/dsh dsh plugin --profile web add <path-or-repo>
```

then restart `dsh --profile web` and reload the page. The API liveness probe is `GET /mcp-manager/api/ping`. Set `HOME`, `USERPROFILE`, and `DSH_HOME` to a scratch directory for `dsh`/`dsh plugin` runs — never let a test touch the real profile.

Tests that may read or write a real profile must also set scratch `HOME`, `USERPROFILE`, and `DSH_HOME` before importing modules that resolve profile paths. `homedir()` uses `USERPROFILE` on Windows, and module-level paths can be fixed at import time; see `test/oauth-discovery.test.js` for an isolation assertion.

Real-harness verification of the 0.2.x contract: `node scripts/verify-deferral-dsh.mjs <npm prefix containing @deepseek-ai/dsh>` boots a disposable profile with a mock MCP server and asserts the assembly, the hiding mechanism (`deferLoading` on `0.2.2+`, the waterfall filter on `0.2.1`), broker dispatch, PTC access and the toggle — no model request is submitted. Run it once per declared `0.2.*` release; the result JSON records the contract it observed, so a `0.2.1` pass is not evidence for `0.2.2`.

The broker's harness-facing contract is covered by `test/broker-presentation.test.js` (waterfall payloads, per-assembly mode changes) and `test/on-demand-deferral.test.js` (missing `tools` array, `deferLoading` marking and the toggle re-registration); run both when touching tool registration or the guards.

For timeout changes, run `node --test test/tool-timeout.test.js` and use `scripts/verify-timeout-dsh.mjs` with a temporary DSH installation to check long calls through all three transports, the native broker, and the plugin default. Record platform and DSH-version coverage separately; a local timeout is not evidence that the remote operation stopped. See `docs/release-v0.14.0.md` for the existing procedure and its boundaries.

Optional static audit — [build-dsh-plugin](https://github.com/AI-Scarlett/build-dsh-plugin) is a third-party Agent Skill used as a checklist, not a dependency:

```sh
node <build-dsh-plugin>/build-dsh-plugin/scripts/audit-plugin.mjs "$PWD"
```

Two of its hard blockers are reviewed false positives here and must not be "fixed" by obfuscating the code: the `shell: true` text quoted inside the `spawnStdio` doc comments (the real `spawn` call uses `shell: isWin`, guarded by `quoteWindowsToken`), and the `warn` on the legacy-plaintext path that logs a server *name* and never a credential value. (These anchors drift when code is inserted above them — re-grep before trusting them; as of 0.13.0 they are `lib/index.js:129`, `:1726` and `:803`.) Re-read the flagged lines; treat the *unmet checks* (test script, pinned source, verification/next-gate docs) as real. Runtime points require `--evidence <file>`, a self-reported record — never claim them without a real disposable-profile run.

## Release

Every user-visible change ships as a versioned release: bump the version, sync the docs, commit, then **tag** so consumers can pin `dsh plugin add <repo>#<ref>`. Steps:

1. Bump `version` in `package.json` (semver).
2. Update `README.md` and `README.zh-CN.md` — keep both in sync with the behavior change.
3. Commit on `main`, then create an **annotated** tag on that exact commit and push both:

   ```sh
   git tag -a v0.5.0 -m "dsh-mcp-manager v0.5.0: <one-line summary>"
   git push origin main v0.5.0
   ```

- Tags are **annotated**, not lightweight — match the existing `v0.2.0` style (a `tagger` plus a one-line message).
- The tag must point at the commit that actually carries the release (on `main`).
- Every `vX.Y.Z` gets a tag — never ship a version without one.

## Gotchas

- Changing the client registration/redirect logic requires re-testing a full OAuth round trip — the provider must allow loopback redirects (`http://localhost:<port>/callback`, or the fixed/override address the server resolves).
- Only `tools` capability is bridged; `resources`/`prompts` are intentionally not.
- Client half is hand-written inside a module factory — no JSX transform available; edit carefully or regenerate deliberately.
